# 06. Данные: хранилище, даты, чистая логика

У «Ритма» нет сервера. Всё хранится на устройстве и работает без интернета — для трекера
привычек это естественно (и это называют offline-first).

## Три слоя

```
src/lib/       чистые функции: даты, серии, статистика     ← не знают про React и телефон
src/store/     состояние и его сохранение (Zustand)         ← не знает про экраны
src/app/       экраны: читают хранилище, вызывают действия
```

Правило зависимости — только вниз. Экран знает про хранилище, хранилище — про `lib`,
а `lib` не знает ни о ком. Поэтому логику можно проверить тестами без телефона.

## Форма данных (`src/lib/habits.ts`)

```ts
type Habit = {
  id: string;
  title: string;
  emoji: string;
  color: HabitColor;      // 'mint' | 'blue' | …  — имя, а не hex: цвет зависит от темы
  days: number[];         // дни недели: 0 — понедельник … 6 — воскресенье
  target: number;         // сколько раз в день (1 — обычная «галочка»)
  unit: string;           // «стакан», «страница»; пусто, если target = 1
  reminder: string | null; // 'HH:MM'
  createdAt: DayKey;
};

type Log = Record<string, Record<DayKey, number>>;
// { 'habitId': { '2026-10-12': 1, '2026-10-13': 3 } }
```

Отметки лежат **отдельно** от привычек, словарём «привычка → день → сколько раз». Вопрос
«сделано ли сегодня» — одно обращение `log[id]?.[day]`, без перебора массива. Нулевые
значения не хранятся: `setCount(…, 0)` удаляет ключ, хранилище не растёт от снятых отметок.

## Даты — главный источник багов (`src/lib/dates.ts`)

День хранится **строкой `'YYYY-MM-DD'` в местном времени** (`DayKey`), а не объектом `Date`
и не числом миллисекунд.

| Почему | Что было бы иначе |
| --- | --- |
| Строка однозначна | `new Date().toISOString()` даёт дату **в UTC**: в Москве в 01:30 ночи это ещё «вчера» — отметка уходит не в тот день |
| Строки сравниваются как даты | `'2026-10-09' < '2026-10-13'` — можно писать `day >= habit.createdAt` |
| Сериализуется как есть | `Date` в JSON превращается в строку и обратно сам не возвращается |
| Ключ словаря | `log[id][day]` |

`toKey(date)` собирает строку из `getFullYear()/getMonth()/getDate()` — это местное время.
`fromKey` создаёт дату через `new Date(y, m - 1, d)`, а не `new Date('2026-10-13')`: строка
такого вида разбирается как **UTC**, и западнее Гринвича получился бы предыдущий день.

Сдвиг на N дней — `setDate(getDate() + n)` (сам переносит через месяц и год), а не
«плюс N × 24 часа»: при переходе на летнее время сутки длятся 23 или 25 часов. По той же
причине `diffDays` сравнивает **полдни**, а не полуночи, и округляет результат.

Неделя начинается с понедельника: `weekday()` переводит JS-нумерацию (0 — воскресенье) в
нашу (0 — понедельник) формулой `(getDay() + 6) % 7`.

### «Сегодня» меняется, пока приложение открыто (`src/hooks/use-today.ts`)

Сайт перезагружают, приложение — сворачивают. Вечером свернули, утром открыли: процесс тот
же, компоненты те же. `useToday()` обновляет день, когда приложение возвращается на экран
(`AppState` → `'active'`) и раз в минуту — чтобы поймать полночь.

## Правила серии (`currentStreak`)

Серия — то, ради чего человек открывает трекер, поэтому правила продуманы:

- дни, на которые привычка **не запланирована**, серию не рвут (привычка по будням
  переживает выходные);
- **сегодня**, пока не выполнено, серию не рвёт — день ещё идёт;
- первый пропущенный запланированный день в прошлом — серия обрывается.

То же с процентом выполнения: незаконченное «сегодня» не учитывается, иначе каждое утро
статистика падала бы. Все эти случаи закреплены тестами в `habits.test.ts`.

## Хранилище (`src/store/store.ts`)

Zustand — как в веб-проектах:

```ts
const habits = useStore((s) => s.habits);          // подписка на часть состояния
const tapHabit = useStore((s) => s.tapHabit);      // действие
```

Компонент перерисовывается только при изменении выбранной части. Поэтому селектор
возвращает то, что лежит в хранилище (`s.habits`), а производное (привычки на день, серии)
считается в компоненте чистыми функциями. Селектор, создающий новый массив на каждый вызов
(`s.habits.filter(…)`), вызывал бы бесконечные перерисовки.

Состояние не мутируется: `setCount` возвращает **новый** объект журнала. Иначе Zustand не
увидит изменения (сравнивает по ссылке).

### Сохранение: `persist` + AsyncStorage

```ts
persist(creator, {
  name: 'ritm',                                    // ключ в хранилище
  version: 1,
  storage: createJSONStorage(() => AsyncStorage),
  partialize: ({ habits, log, settings, seeded }) => ({ habits, log, settings, seeded }),
  migrate: (persisted, version) => persisted,
  onRehydrateStorage: () => (state) => { … useStore.setState({ hydrated: true }) },
})
```

**AsyncStorage** — «ключ → строка» на устройстве. В браузере он сам работает поверх
`localStorage`, так что код один. Отличие от `localStorage` — он **асинхронный**.

### Гидрация и флаг `hydrated`

Чтение с диска занимает миллисекунды, но первый рендер случается раньше. В этот момент в
хранилище начальные значения — пусто. Что пойдёт не так без флага:

1. мигнёт экран «привычек нет»;
2. код «первый запуск → создать демо» перезапишет настоящие данные.

Поэтому `hydrated` выставляется в `onRehydrateStorage`, а корневой `_layout.tsx` до этого
момента рисует пустой фон цвета темы вместо экранов (это доли секунды).

`partialize` перечисляет, что сохранять: функции-действия и сам `hydrated` на диск не идут.

### Версии данных

Приложение обновится, а данные на телефоне останутся старого вида. `version` + `migrate` —
место, где старые данные приводятся к новой форме:

```ts
migrate: (persisted, version) => {
  if (version < 2) persisted.habits.forEach((h) => (h.note ??= ''));
  return persisted;
}
```

На сайте можно «просто почистить localStorage». В приложении это означает потерю данных у
всех пользователей при обновлении.

### Демо-данные

На первом запуске пустой экран ничего не объясняет. `seed()` создаёт несколько привычек и
историю за 14 недель. Генератор случайных чисел — с фиксированным зерном (`mulberry32`):
данные одинаковые при каждом запуске, а значит, годятся для тестов и скриншотов. Флаг
`seeded` не даёт демо вернуться после «Удалить всё».

## Когда этого мало

| Задача | Чем |
| --- | --- |
| Тысячи записей, поиск, связи | `expo-sqlite` (SQLite на устройстве) |
| Токены, пароли | `expo-secure-store` (Keychain / Keystore) — **не** AsyncStorage |
| Данные с сервера, кэш | TanStack Query |
| Синхронизация между устройствами | бэкенд (например, Supabase — как в «Летучке») |
