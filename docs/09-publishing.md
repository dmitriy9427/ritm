# 09. Проверки и публикация

## Проверки

```bash
npm run check      # линтер + типы + тесты — перед каждым коммитом
```

| Команда | Что делает |
| --- | --- |
| `npm run lint` | `expo lint`: ESLint с правилами Expo и React (в том числе правила хуков и React Compiler) |
| `npm run typecheck` | `tsc --noEmit` — строгий TypeScript, типизированные адреса экранов |
| `npm test` | Jest с пресетом `jest-expo` — 30 тестов логики |

Те же проверки запускает GitHub Actions перед публикацией: сломанный код на сайт не попадёт.

## Четыре способа показать приложение

| Способ | Что нужно | Кому подходит |
| --- | --- | --- |
| **Веб-версия** | ничего, ссылка открывается в браузере | портфолио: смотрят с компьютера |
| **Expo Go** | приложение Expo Go на телефоне + запущенный `npm start` | разработка и показ «вживую» |
| **Своя сборка (EAS Build)** | аккаунт Expo; для iOS — Apple Developer (99 $/год) | установка на телефон без компьютера |
| **Магазины** | Apple Developer; Google Play (25 $ разово) | настоящий релиз |

## Веб-версия на GitHub Pages

```bash
npm run export:web     # → dist/
```

Команда делает `expo export -p web` и копирует `index.html` в `404.html`.

Три настройки, без которых на Pages не заработает:

1. **`"output": "single"`** (`app.json`) — одностраничное приложение: один `index.html`,
   навигация на клиенте.
2. **`baseUrl`** (`app.config.js`). Pages отдаёт сайт из подпапки
   `https://<user>.github.io/ritm/`, и пути к скриптам должны начинаться с `/ritm`.
   Значение берётся из переменной окружения, чтобы локально всё работало с корня:

   ```js
   experiments: { ...config.experiments, baseUrl: process.env.EXPO_BASE_URL ?? '' }
   ```

3. **`404.html`**. Прямой заход на `/ritm/stats` — такого файла нет, Pages отдаёт `404.html`.
   Раз это копия `index.html`, приложение запускается и само открывает нужный экран.

Workflow (`.github/workflows/pages.yml`): `npm ci` → `npm run check` → `npm run export:web`
с `EXPO_BASE_URL=/ritm` → публикация `dist/`.

Чего в веб-версии нет: вибрации, уведомлений, системных жестов. Это витрина, а не замена
приложению.

## Expo Go

```bash
npm start
```

QR-код из терминала — камерой (iOS) или из приложения Expo Go (Android). Телефон и компьютер
в одной сети Wi-Fi. Подробно — [глава 02](02-running.md).

Ограничение: в Expo Go работают только нативные модули, которые в него встроены. Все
модули «Ритма» там есть. Понадобится модуль не из набора (например, виджеты) — нужна своя
сборка.

## Своя сборка: EAS Build

EAS — облачный сервис Expo: собирает `.ipa` и `.apk/.aab` на своих серверах. **Собрать
iOS-приложение можно без Mac и без Xcode.**

```bash
npm install -g eas-cli
eas login                                   # аккаунт на expo.dev (бесплатный тариф есть)
eas build:configure                         # создаст eas.json

eas build -p android --profile preview      # .apk — ставится на любой Android по ссылке
eas build -p ios --profile preview          # нужен Apple Developer; устройства регистрируются
```

Профили в `eas.json`:

| Профиль | Что это |
| --- | --- |
| `development` | «свой Expo Go»: ваши нативные модули + обновление кода с компьютера |
| `preview` | готовое приложение для тестировщиков (ссылка / QR) |
| `production` | сборка для магазина |

Перед первой сборкой в `app.json` добавляются уникальные идентификаторы:
`ios.bundleIdentifier` и `android.package` (например, `com.dmitriy.ritm`). Их нельзя
поменять после публикации.

### Локальная сборка

```bash
npx expo run:ios        # нужен Mac + Xcode
npx expo run:android    # нужен Android Studio
```

Команда создаёт папки `ios/` и `android/` (это называется prebuild) и собирает проект. В
репозитории этих папок нет: они **порождаются** из `app.json` и плагинов, руками в них
ничего не правят.

## Магазины

```bash
eas build -p ios --profile production && eas submit -p ios
eas build -p android --profile production && eas submit -p android
```

Понадобится: иконка 1024×1024, скриншоты для разных экранов, описание, политика
конфиденциальности (даже если данные не покидают устройство), возрастной рейтинг. Проверка
в App Store — от суток; в Google Play новые личные аккаунты обязаны сначала провести
закрытое тестирование.

## Обновления без магазина

`expo-updates` + `eas update` доставляют **JavaScript-часть** приложения напрямую на
устройства, минуя проверку магазина: исправление опечатки или бага — за минуты. Изменения
нативной части (новый модуль, разрешение, версия SDK) — только новой сборкой.

## Версии

| Поле (`app.json`) | Что это |
| --- | --- |
| `version` | версия для людей: `1.0.0` |
| `ios.buildNumber`, `android.versionCode` | номер сборки: растёт с каждой загрузкой в магазин |

Обновление Expo SDK (выходит несколько раз в год):

```bash
npx expo install expo@latest
npx expo install --fix      # подтянуть совместимые версии остальных пакетов
npx expo-doctor             # проверить проект
npm run check
```

Перед обновлением — прочитать заметки к выпуску SDK: там список изменений, ломающих код
(в этом проекте такие уже встретились — [lessons.md](lessons.md)).
