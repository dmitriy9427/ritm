# 01. React Native и Expo

## Сайт и приложение — в чём разница

Сайт работает в браузере: HTML, CSS, DOM. Мобильное приложение — программа, установленная
на телефон; её интерфейс состоит из **нативных элементов** системы: `UIView` на iOS,
`android.view.View` на Android. У них нет ни HTML, ни CSS.

**React Native** — это React, который вместо DOM-элементов создаёт нативные:

```
        Ваш код (один)                 React Native              Экран телефона
  <View><Text>Привет</Text></View>  ──▶  iOS:     UIView + UILabel
                                    ──▶  Android: ViewGroup + TextView
                                    ──▶  Web:     <div> + <div dir="auto">   (react-native-web)
```

Поэтому:

- знания React переносятся целиком — компоненты, хуки, состояние, контекст;
- **не переносятся** HTML-теги и CSS: вместо них свои компоненты и стили-объекты
  (глава 03 — словарь соответствий);
- приложение выглядит и ощущается «родным»: прокрутка, жесты, клавиатура — системные.

Это **не** сайт в обёртке (WebView), как Cordova или Telegram Mini App. Сравните с «Мятой»:
там обычный сайт внутри Telegram, здесь — настоящие нативные элементы.

## Что такое Expo

React Native сам по себе — библиотека. Чтобы собрать приложение, нужны Xcode, Android Studio,
настройка нативных проектов на Swift/Kotlin. **Expo** — набор инструментов поверх React
Native, который это прячет:

| Что даёт Expo | Зачем |
| --- | --- |
| **Expo Go** — приложение из App Store / Google Play | Открыть свой проект на телефоне по QR-коду, без сборки |
| **Expo SDK** — модули `expo-haptics`, `expo-notifications`… | Доступ к возможностям телефона одинаковым API на iOS и Android |
| **Expo Router** | Навигация из файлов, как в Next.js |
| **EAS** — облачная сборка | Собрать `.ipa`/`.apk` и отправить в магазины без Mac и Xcode |
| **Веб-цель** | Тот же код собирается в сайт |

В проекте нет папок `ios/` и `android/` — они создаются автоматически при сборке
(*Continuous Native Generation*). Нативные настройки (иконка, имя, разрешения) описаны в
`app.json`.

## Один код — три платформы

| Платформа | Как запускается | Что проверено в этом проекте |
| --- | --- | --- |
| iOS | Expo Go или своя сборка | запускать вам (нужен iPhone) |
| Android | Expo Go или своя сборка | запускать вам (нужен Android) |
| Web | `npm run web`, сборка на GitHub Pages | проверено автотестами в браузере |

Большая часть кода одинакова. Различия — там, где различаются сами платформы:

```ts
import { Platform } from 'react-native';

if (Platform.OS === 'web') { /* в браузере вибрации нет */ }
behavior={Platform.OS === 'ios' ? 'padding' : undefined}
```

В «Ритме» такие места собраны в папке `src/platform/` (глава 08): остальной код не знает,
на какой он платформе.

## Как это работает внутри

```
┌─ JS-поток ─────────────┐        ┌─ UI-поток (главный) ──────────┐
│ ваш React-код          │  ───▶  │ нативные элементы, прокрутка, │
│ состояние, логика      │        │ жесты, анимации Reanimated    │
└────────────────────────┘        └───────────────────────────────┘
```

- Ваш JavaScript выполняется движком **Hermes** в отдельном потоке.
- Интерфейс рисует система в главном (UI) потоке.
- Если JS занят тяжёлым расчётом, React не может обновить экран — но прокрутка и
  анимации, которые живут в UI-потоке, продолжают работать. Это главная причина, почему
  анимации в RN делают через Reanimated (глава 07), а не через `setState`.

## Что нужно знать про Expo Go

Expo Go — готовое приложение с набором встроенных нативных модулей. Ваш JS-код загружается
в него по сети.

- ✅ Всё, что есть в Expo SDK (в «Ритме» — всё, что используется).
- ❌ Библиотека со **своим** нативным кодом, которого нет в Expo Go (платежи, Bluetooth,
  виджеты): нужна *development build* — своя сборка приложения (`eas build --profile
  development`). Код тот же, просто «оболочка» ваша.

## Версии

Expo выпускает новый SDK несколько раз в год, и API меняются. В этом проекте — **SDK 57**
(React Native 0.86, React 19). Правило: пакеты с нативным кодом ставятся командой
`npx expo install <пакет>` — она подбирает версию, совместимую с вашим SDK.
`npm install` поставил бы последнюю, которая может не подойти.

Два изменения SDK 57, на которые я наткнулся (подробности — [lessons.md](lessons.md)):
вкладки теперь импортируются из `expo-router/js-tabs`, а `StyleSheet.absoluteFillObject`
убрали. Документация конкретной версии: `https://docs.expo.dev/versions/v57.0.0/`.
